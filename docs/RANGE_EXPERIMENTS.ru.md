# Эксперименты на дальность (пара v1, 2.4 ГГц)

Цель: выжать **больше стабильности на краю** и честные лишние километры с **текущей** пары, а не сменить частоту.

База, которую уже даёт сток ELRS на этом железе: порядка **~30 км**. GerdaLRS не обещает ×2. Физика (1 Вт на Ranger Nano, одна антенна на FlyFish 9624R, LoRa SF8 / BW 800 кГц на 50 Гц, шум ISM 2.4) остаётся пределом. Ожидаемый выигрыш — меньше фейлов на 25–35 км и, если повезёт, скромная прибавка failsafe-дистанции при тех же антеннах и погоде.

**Не часть этого эксперимента:** 750 МГц, 900 МГц, dual-band TX, CUSTOM_2640 как «дальность» (на фронтенде ~2.4–2.5 ГГц сдвиг частоты почти наверняка ухудшит КСВ). Secure Link для max-range полётов **выкл**.

Железо: TX RadioMaster Ranger Nano SX1280 (Lua `RM Ranger Nano`, до 1000 мВт) + RX FlyFish 9624R / generic ESP32-C3 LR1121, одна антенна. Cross-chip: только стандартный LoRa 2.4. Самый медленный общий режим — **50 Гц** (`RATE_LORA_2G4_50HZ`; 25 Гц 2.4 в таблице SX1280 нет). TOA ≈ 10.8 мс в слоте 20 мс; DVDA (`numOfSends=2`) на 50 Гц **не влезает**.

## Lua-базовый набор для 30 км+ (A и B одинаковый)

На аппаратуре, **до** сравнения прошивок:

| Параметр | Значение | Зачем |
| --- | --- | --- |
| Packet Rate | **50 Hz** | Макс. чувствительность общего LoRa SX1280↔LR1121 (~−115 dBm) |
| Telem Std | **1:16** | Реже — мало данных dynpower; чаще — крадёт RC на краю |
| Switch | **Wide** | Как на рабочем 30 км скрине |
| Link Mode | **Normal** | Не Gemini (у Nano один RF path в этом сценарии) |
| Model Match | **Off** | Меньше сюрпризов UID |
| TX Power | **1000 mW** | Потолок модуля |
| Dynamic Power | **On** | В Gerda «Дальность» мощность почти не опускается на краю |
| Wi‑Fi / Bluetooth TX | выкл в полёте | Не гадить себе в ISM |

Профиль Gerda (только на стороне Gerda, вкладка Опции Web UI): **Дальность**. Secure: **выкл**. Умный FHSS: **выкл** в первом A/B; второй проход — вкл, если трасса в городе / Wi‑Fi. Диапазон: **ISM 2.4**, не CUSTOM_2640.

После выбора Дальность перезагрузите TX: EEPROM модели получит 50 Гц / 1:16. Lua это увидит; не крутите rate вверх mid-test.

## Что делает профиль «Дальность» (без ручной крутилки в полёте)

| Рычаг | Сток ELRS | Дальность Gerda |
| --- | --- | --- |
| Rate / telem boot | как в Lua | 50 Гц + 1:16 |
| Dynpower boost-to-max | LQ ≤ 50 или drop ≥ 20 | LQ ≤ **80** или drop ≥ **15** |
| Dynpower power-down | LQ ≥ 95 | LQ ≥ **99** |
| Dynpower LQ step-up | LQ ≤ 85 | LQ ≤ **90** |
| MSP в RC-слоте | всегда может уйти | defer при LQ < 70 |
| Telem mid-flight | фиксированный denom | LQ&lt;70 → 1:32, LQ&lt;50 → 1:64, выход LQ&gt;85; RX узнаёт через SYNC `newTlmRatio`. Не NO_TLM, не трогает MSP 1:2 |

Файлы: `src/lib/GERDA/gerda_link.*`, хук `UpdateTlmRatioEffective()` в `tx_main.cpp`, пороги в `dynpower.cpp`.

## A/B чеклист (Gerda vs сток)

Один день, один комплект, меняется **только прошивка** (и профиль Gerda). Иначе сравниваете антенны.

1. Одинаковые антенны, поляризация, длина кабеля, обжим. Не «на этой неделе другая патч».
2. Одинаковый аккумулятор TX (напряжение на старте, тот же XT30). Ranger Nano падает с 1 Вт при просадке — логируйте Vbat.
3. Одинаковая ориентация самолёта / крыла / антенн RX. Одна антенна FlyFish: не прячьте U.FL за карбоном.
4. Погода в блокнот: температура, ветер, видимость, влажность, облачность. Дождь и инверсия ломают сравнение.
5. Трасса: те же километровые точки (GPS OSD). Фиксируйте азимут на TX.
6. Сначала **сток ELRS** (тот же commit-base `7684347`, без Gerda-флагов), затем Gerda «Дальность», затем (опционально) Gerda + Умный FHSS.
7. Не включать Secure. Не включать CUSTOM_2640. Не менять Lua rate между прогонами.
8. Arm / failsafe / LQ на OSD как обычно. Телеметрию не выключать полностью — dynpower и логи нужны.

## Что писать в лог

Каждый прогон, одни и те же столбцы:

- Прошивка: `stock` / `gerda-range` / `gerda-range+fhss`
- Время, погода, Vbat TX старт/финиш
- GPS расстояние в момент: LQ 90 / 70 / 50 / 20, SNR, RSSI
- Точки **25 / 30 / 35 км**: LQ, SNR, RSSI, telem (идёт / редкая / пропала), мощность TX если видно
- Дистанция **первого failsafe** и дистанция **восстановления**
- Были ли MSP/LUA-команды в полёте (на Дальности они должны откладываться при низком LQ)
- После посадки: Web UI Опции → блок `Gerda range stats` (miss % по каналам, denylist, `fec_recoveries`)

OSD: LQ, SNR, RSSI1, TX pwr, GPS dist, GPS spd. Если есть blackbox / telemetry log EdgeTX — снимите.

## Метрики успеха (честные)

Считать Gerda лучше стока **на этой паре**, если при тех же условиях:

1. Failsafe дальше, чем сток, **или** на той же дистанции LQ не сыпется пачками (меньше дыр 0/50).
2. На **30 км** LQ стабильнее (медиана выше / меньше провалов &lt;50).
3. На **35 км** либо есть линк, которого не было, либо failsafe наступает заметно позже.
4. Телеметрия на краю реже, но **управление** не хуже — это и есть backoff, не баг.

Не успех: «включили 2640 и стало дальше» (скорее наоборот). Не успех: Secure ON как условие дальности.

Один полёт ничего не доказывает. Минимум два прогона сток и два Gerda в похожую погоду.

## Флаги Gerda для прогона

| Флаг | Max-range A/B | Когда иначе |
| --- | --- | --- |
| `gerda-profile` = 1 Дальность | **да** | — |
| `gerda-secure` = 0 | **да** | тесты анти-takeover отдельно |
| `gerda-fhss` = 0 | первый A/B | =1 если Wi‑Fi/bando, hops всё равно стоковые |
| `gerda-2g4` = 0 ISM | **да** | 2640 не для дальности |

Код дальности **не** требует Secure ON.

## FEC / erasure (почему не в эфире)

Полный межпакетный FEC на 50 Гц потребовал бы второй посылки или отдельного parity-пакета. TOA ~10798 мкс, интервал 20000 мкс — DVDA не помещается. Красть RC-слот под parity на краю хуже, чем просто отдать слот управлению (это уже делает telem backoff).

В этом PR:

- Примитив XOR двух payload (OTA4 8 B / OTA8 13 B): `src/lib/GERDA/gerda_fec.*`
- Окно из двух пакетов считает parity; `gerda_fec_recover(good, parity, missing)` восстанавливает один erasure
- Native-тесты это покрывают. Счётчик `fec_recoveries` в `/config` → Web UI
- **В эфир не вшито.** `gerda_link_feature_enabled(INTERPACKET_FEC) == 0`
- Сток и так держит last-good RC до `DisconnectTimeoutMs` (на 50 Гц 4000 мс) — это и есть текущее «удержание» без лишнего airtime

Следующий чистый шаг (не сейчас): слать XOR-parity **вместо** очередного TLM, когда backoff уже на 1:64, тем же `PACKET_TYPE_DATA` только если TX и RX договорятся sync-битом. Пока этого бита нет — не ломаем OTA.

## Умный FHSS в этом эксперименте

Default **выкл**. Имеет смысл во **втором** прогоне Gerda, если 2.4 забит: гистограмма CRC/RSSI, denylist ≤25% каналов, hops **как у ELRS** (иначе SX1280 и LR1121 разъедутся). Miss на denylist не бьёт LQ и не крутит AFC. См. `docs/FHSS.ru.md`.

## После полёта

Wi‑Fi AP `GerdaLRS TX` / `GerdaLRS RX`, `http://10.0.0.1/`, вкладка Опции: блок статистики hop CRC. Это не телеметрия с борта — только то, что модуль накопил, пока был включён Умный FHSS.

Релизные `.bin` этим чеклистом не публикуются.
